# Student Learning (Ontario Grades 6–12)

Student Learning is a section of FlowCompanion for students in Ontario, Grades 6 to 12. It shows the official curriculum, teaches from it, checks answers, tracks progress by expectation, schedules reviews and plans study time. It works offline; an AI tutor is optional.

What is and isn't covered is listed in [CURRICULUM_COVERAGE.md](CURRICULUM_COVERAGE.md), which is generated from the app's data. In short: **every Grade 6–12 course is listed and its expectations can be read in full, but FlowCompanion's own lessons and checked practice exist for 80 mathematics expectations (Grades 6–9) only.** For everything else there are the Ministry's own teacher supports (where published) and, if you turn it on, the AI tutor.

FlowCompanion is not affiliated with or endorsed by the Ontario Ministry of Education. Its progress indicators are not marks or achievement levels.

## Getting started

1. Open **Student Learning** in the sidebar. The first time, a short setup asks for a first name or nickname and a grade. Courses, goals, explanation preference, study times and a profile PIN are optional and can be changed later in **Learning settings**.
2. Each profile is separate. Lessons, answers, progress, plans and tutor conversations belong to one profile and are invisible to the others. A profile PIN stops other people on the same computer from opening it (5 wrong tries lock it for 5 minutes; a parent with the Parental Learning Controls PIN can remove a forgotten PIN in Settings → Student Learning).
3. **Curriculum** lists courses by grade and subject with course codes, types and prerequisites, and searches every expectation. Each expectation page shows the official wording in a box marked as the Ministry's text, with a link to the Ministry page, and offers the ways to study it that actually exist for that expectation.

## The official curriculum

- **Source:** the Ministry's Curriculum and Resources site, dcp.edu.gov.on.ca, through the public data service behind it. The text is stored word for word (formatting reduced to a safe subset of HTML), with the Ministry's numbering (e.g. B1.4), strands, overall expectations and teacher supports.
- **Copyright:** © King's Printer for Ontario. Reproduced for non-commercial educational use without changes, under the [Ontario copyright terms](https://www.ontario.ca/page/copyright-information). The app says so on every page that shows curriculum text.
- **Offline:** the curriculum ships with the app (`resources/curriculum/ontario.json.gz`, 3 MB) and is copied into its own local database (`curriculum.db`) on first start.
- **Verification states:** *verified* (from the Ministry site), *PDF only* (the Ministry publishes the course only as a PDF; it is listed with a link but its expectations are not imported or paraphrased), *unverified* (imported from a file by hand), *changed on the Ministry site*, *no longer published*.
- **Updates:** Student Learning → Coverage → "Check the Ministry site for changes" downloads the public data again (about 40 requests, no personal data), shows what changed, and applies it only when asked. Earlier wording is kept in a revision history. Developers can run `npm run curriculum:verify` (exits non-zero on any difference) and `npm run curriculum:fetch`.
- **Last check:** on 29 October 2026 the shipped curriculum matched the live Ministry site exactly (297 courses, 11,153 expectations, no differences).

## Lessons

A lesson follows nine steps: learning goal → check earlier skills → explanation → worked example → guided practice → your turn → quick check → key ideas → what next. Lessons can be paused, resumed (also after a restart, at the same step), repeated or abandoned. Modes: complete lesson, short explanation, timed session, practice only, revision before a test, one concept, challenge, review my mistakes.

There are three kinds of lesson, always labelled:

| Kind | When | What it contains |
| --- | --- | --- |
| **FlowCompanion lesson** | The 80 mathematics expectations with an authored skill pack | Explanation, worked example and alternative explanations written for the app; questions generated by code with answer keys checked twice (below) |
| **From the Ministry supports** | Expectations whose Ministry page has teacher supports | The official expectation and the Ministry's supports quoted verbatim, with reflection prompts; no invented content |
| **AI lesson** | Any expectation, only with AI tutoring turned on | Written by your AI provider from the official text. Marked "AI-written". Its questions' keys are not checked by code and count for less in progress. If the AI's output is not valid, the app says so and shows nothing. |

"Explain it another way" offers: more simply, an analogy, step by step, a picture, compare with something else, another example. Authored packs have their own versions; otherwise the AI writes one (if allowed).

## Questions and checking answers

Question types: multiple choice, multiple select, true/false, numeric (fractions, mixed numbers, decimals, percents, units, tolerances, "simplest form" when asked), algebraic expression (equivalence by polynomial comparison, "simplified" when asked), short answer, fill in the blanks, matching, ordering, code tracing, and written responses with a rubric.

- **Generated questions** come from 35 skill packs. Every generated question's key is recomputed by a second, independent calculation before it is shown; a question that fails is thrown away. The content test suite generates questions for every pack at every difficulty (300 seeds per level in the latest run) and checks that keys mark themselves right, known wrong answers are recognised, all text renders (no `NaN`/`undefined`, valid LaTeX) and every pack maps to a real expectation. In that run no question had to be discarded.
- **Numbers are exact:** fractions use exact rational arithmetic, so 1/3 + 1/6 is 1/2, not 0.49999.
- **Feedback** is immediate in practice: right or wrong, the likely misconception when a wrong answer matches a known one (e.g. adding denominators), a way to fix it, the worked solution, and a similar question.
- **Hints** are visible and counted. An answer given after hints counts as "with help".
- **Written answers** are never marked by code. The student can score themselves against the rubric; with AI tutoring on, they can ask for AI feedback, which is labelled and does not count as evidence.
- **Answer keys stay in the main process** until a question is answered, so they cannot be read from the page.
- **Integrity:** quiz types state their rules before starting (practice: hints and feedback; diagnostic: no hints, feedback at the end; practice test: optional timer, results at the end). Timers are off by default and extra time can be turned on per student.

## Progress, gaps and review

Progress is tracked per specific expectation from the last 12 marked answers:

| Rule | Value |
| --- | --- |
| Weight by difficulty (levels 1–4) | 0.6, 1.0, 1.2, 1.3 |
| Age | half the weight after 30 days |
| Answer after hints | 0.6 credit |
| Answer on an AI-written question | 0.4 weight |
| Proficient | at least 3 correct without hints and about 80% weighted (both adjustable in Settings → Student Learning) |

Statuses: not assessed, not yet, in progress, developing, proficient, extension-ready (strong, independent, harder questions on more than one day), review (was proficient; due for review). The app explains each status and states that these are not Ontario achievement levels, marks or predictions.

- **Difficulty adapts** but never after a single answer: up after two independent correct answers, down after two wrong answers among the last three.
- **Gaps** detected: the same mistake more than once, an earlier skill that needs work (from the packs' prerequisites), recognising answers but not producing them, relying on hints, and not practised for a while.
- **Spaced review:** after proficiency, reviews are scheduled at 1 day, 3 days, then growing intervals (at most 120 days). A review with mostly wrong or helped answers resets the interval to 1 day. When a test date is set, the review is moved before it. A daily reminder (without the student's name) can say that reviews are due.
- **Reflection:** students can record confidence and a note. This is shown as their own view, never as evidence.

## Planner, assignments and assessments

- **Study plans** (test preparation, weekly, daily review, assignment) are proposals until approved. Approval creates calendar events (category "study", with reminders) and tasks in a "Study plan" list, linked to the plan. Proposed times avoid existing calendar events and follow the student's study days, time and session length. Missed sessions can be rescheduled; archiving can remove future events. A per-student "schedule automatically" option exists and is off by default.
- **Assignments** have due dates and steps that depend on the kind: for a test or exam, a diagnostic, review of earlier skills, guided then independent practice, a mixed practice test and a review of recurring mistakes; for an essay, understanding the task, gathering evidence, thesis and outline, draft, feedback, revision and a final check; projects, presentations and labs have their own. Optional AI feedback on a draft is labelled and never a mark.
- **Assessment builder:** builds practice tests from chosen expectations with generated items (and AI items only if allowed). Every item must be reviewed before the assessment is marked reviewed; items can be removed or regenerated; export to Markdown or JSON. Written items carry a practice rubric using the four Growing Success (2010) achievement-chart categories — Knowledge and Understanding, Thinking, Communication, Application — with a note that it is a practice rubric, not an official evaluation.

## AI tutor

Off until the student turns it on in Learning settings, after a dialog listing exactly what is sent. A switch in Settings → Student Learning can turn it off for everyone; Parental Learning Controls can also lock AI.

- **Sent to the provider:** what the student types, the expectation being studied and its Ministry text, grade, explanation preference, plain-language preference, and — only with a second, separate switch — a short summary of verified progress on that expectation.
- **Never sent:** the student's name, PIN, other profiles or other conversations. An end-to-end test checks the name is absent from every request.
- **Behaviour:** the tutor is instructed to guide with hints and leading questions before giving answers, not to complete graded work, never to present its words as official Ministry material or invent curriculum, to say when it is unsure, and to stay age-appropriate (with a pointer to a trusted adult and Kids Help Phone if a student says they are unsafe). The student's text is fenced as data in the prompt. These are instructions to the model, not guarantees.
- **Limitations:** AI can be wrong, can misread the curriculum, and is not reviewed by a teacher. Its lessons, questions and feedback are always labelled, its question keys are not verified, and its answers count for less in progress. Quality depends on the provider and model the user connects; FlowCompanion has been tested against mock providers and one small local model, not against every provider. Students under a provider's minimum age should ask a parent first (the consent dialog says so).

## Parents

With Parental Learning Controls set up, a parent can (Settings → Student Learning → Parent tools, with the parental PIN):

- view or save a report for a profile **only if the student has chosen to share one**, and only the parts they chose (goals, activity, progress by course). Tutor conversations, answers, written work and reflections are never in it;
- remove a forgotten profile PIN.

Student Learning can be locked like any other section, and is allowed by default in supervised study sessions.

## Privacy

Everything stays on this computer, in the main database (student tables) and `curriculum.db` (public curriculum only, no personal data). Students can export their own records (JSON) or delete them (type DELETE) in Learning settings, and delete their profile. The app-wide "Export everything" leaves student profiles out, because it is available to anyone using the computer and a profile can have its own PIN. Student data is not in the global search index. Approved plan events and tasks are ordinary calendar items and stay if a profile is deleted.

## Accessibility

Per-student text size (up to 160%), an easier-to-read font, plainer language for lessons and the tutor, extra time on timed tests, keyboard-operable questions (including ordering and matching), ARIA labels and live regions for feedback, and math rendered by KaTeX with MathML for screen readers. Not tested with a screen reader or by students with disabilities.

## Educational quality: what has and hasn't been checked

| Check | Status |
| --- | --- |
| Curriculum text matches the Ministry site | Checked automatically (live comparison, 29 Oct 2026: no differences) |
| Every skill-pack mapping points at a real expectation | Checked automatically |
| Answer keys correct for generated questions | Checked automatically by independent recomputation (all 35 packs, 300 seeds per difficulty level) |
| Known misconceptions recognised from wrong answers | Checked automatically for each pack's listed wrong answers |
| Text renders (no NaN/undefined; LaTeX valid) | Checked automatically |
| Mappings fit the expectation's wording | Spot-checked by reading; each mapping states which part of the expectation it practises (see the coverage report) |
| Explanations and examples are pedagogically sound and grade-appropriate | **Not reviewed by an Ontario teacher.** Written to the Ministry wording; needs professional review before classroom use |
| Mastery thresholds are sensible | Design choice, adjustable; not validated against student outcomes |
| AI lessons and tutor | Not quality-checked beyond labelling, JSON validation and the safety instructions in the prompt |

## For developers

- Code: `src/core/curriculum` (import, sanitising, storage, coverage), `src/core/study` (profiles, lessons, quizzes, mastery, planner, assessments, AI), `src/core/study/content` (skill packs), `src/renderer/modules/study` (UI), `scripts/curriculum-cli.ts`.
- Adding a skill pack: write it in `src/core/study/content/math/*.ts` using the helpers in `kit.ts`, include a `selfCheck` that recomputes the key a different way, map it to expectations with a note saying which part it covers, add it to its pack list, then run `FC_CONTENT_ONLY=<pack-id> npx vitest run tests/unit/content.test.ts` and `npm run curriculum:coverage`.
- Tests: `tests/unit/curriculum.test.ts`, `content.test.ts`, `study-core.test.ts`, `study-service.test.ts`, `tests/e2e/study.spec.ts`.
